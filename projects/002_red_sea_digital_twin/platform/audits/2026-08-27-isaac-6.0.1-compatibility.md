# Isaac Sim 6.0.1 container compatibility

- Date: 2026-08-27
- Result: **passed**
- GPU exposed: host GPU 1 only
- Host mutation: none

## Tested boundary

The official `nvcr.io/nvidia/isaac-sim:6.0.1` image was pulled after the
retired Qwen workload was removed. NVIDIA's compatibility checker was launched
in an ephemeral container with only GPU 1 exposed. No project data was mounted,
and no operating-system, kernel, driver, or service configuration was changed.

## Observed result

| Check | Result |
| --- | --- |
| Overall | `System checking result: PASSED` |
| Driver | 580.126.09 supported; checker minimum 535.161 |
| GPU | RTX 5880 Ada Generation supported |
| VRAM | 51.53 GB, excellent |
| CPU | Threadripper 7960X supported; 48 logical cores, excellent |
| RAM | 134.48 GB, excellent |
| Container OS | Ubuntu 24.04.3 LTS supported |
| Display | None detected; expected for headless streaming |

The checker warned that the CPU governor is `ondemand` rather than
`performance`, PCIe currently negotiates x8 on an x16-capable link, IOMMU is
enabled, and swap was fully consumed. These are performance or capacity items,
not compatibility failures.

The checker reported its container-visible storage as sufficient. Operational
decisions continue to use host `df` measurements instead: about 202 GiB was
available after pulling the 21.1 GB Isaac image.

## Decision

Approve the current host for the M0 **isolated Isaac 6.0.1 container path** on
GPU 1. Do not perform the proposed remote in-place OS upgrade. The successful
container check demonstrates that an Ubuntu 24.04 userspace and the existing
driver can run the pinned runtime without risking the shared host boot path.

This approval does not turn the Ubuntu 20.04 host into the eventual production
platform. A clean Ubuntu 24.04 host remains the long-term target, but it is no
longer a blocker for the first scene and WebRTC stream.

## Next gate

Launch the full headless streaming application with persistent cache and log
directories, GPU 1 isolation, explicit ports, and the committed calibration
stage. Record startup time, stream connectivity, stop/restart behavior, GPU
memory, and disk growth.
