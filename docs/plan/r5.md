# The fifth plan: a platform an agent can drive

Everything in `r4.md` is written for somebody with a screen. This is not that.

Nobody builds against a system by hand any more. They point an assistant at it
and describe what they want, and the assistant does the clicking. A platform
that can only be operated through its own application is a platform that has to
be learned before it can be used, and the learning is the sale we keep losing.

So: **every service we have, reachable by an agent, over MCP.** The application
stays — somebody still wants to watch a dive — but it stops being the only door.

## What this is actually for

The pitch is not "we have an API". Everybody has an API.

> Design the experiment in words. Your own assistant lays out the plot, flies
> it, flies it again against everything that could go wrong, and hands back the
> geometry and the coverage and the footage. You write no interface, you
> integrate nothing, and you do not build a simulator.

A customer with a question about a survey pattern should be able to have the
answer in an afternoon, without a single pixel of user interface, from whatever
assistant they already pay for.

## Why ours can be trusted and a wrapper cannot

An assistant asked for a number will produce one. That is the whole risk of
putting an LLM between an operator and a decision, and it is why the careful
buyers — the ones with an asset worth money — will not do it.

This platform is already built so that **it cannot hand anybody a number without
saying who measured it**. `provenance.json` ships with every deliverable and
marks each field measured, derived, chosen or assumed; a fitted seabed says it
is derived and says the depth it holds to; a bench row that cannot name its
water says so rather than implying the default.

Carried into MCP, that becomes the only defensible answer to "how do I know your
AI is not making this up":

**The tools do not return bare numbers. Every value arrives with its provenance,
and an agent that reports one without it is contradicting its own input.**

That is the moat. It is already built. It has never been exposed.

## The tools

Named after the nouns the platform already has, because an agent reading the
tool list should be able to guess the model from it.

**Looking**

| Tool | Gives back |
| --- | --- |
| `places_list` | every place, with depth range and what its ground came from |
| `places_get` | the site record: surveys, cover, water, `calibratedToM` |
| `vehicles_list` | hulls, mass, thrusters, and whether each can actually fly |
| `controllers_list` | what is deployed, and what each has flown |

**Designing**

| Tool | Gives back |
| --- | --- |
| `layouts_create` | a new arrangement of a place |
| `layouts_add_line` | a line of marks between two points at a spacing |
| `layouts_render` | **a PNG of the chart**, which is how a blind agent sees |
| `missions_create` | a plan of work: stages, in order, over a place |

**Running**

| Tool | Gives back |
| --- | --- |
| `dives_estimate` | what it will cost and how long, *before* anything runs |
| `dives_start` | a run |
| `dives_watch` | where it is, without video |
| `sweeps_run` | one mission against every doubt, N times each |

**Answers**

| Tool | Gives back |
| --- | --- |
| `dives_result` | score, drift, energy, each tagged |
| `dives_deliverables` | track, coverage, planting, colonies — GeoJSON |
| `dives_frame` | what the camera saw at a time |
| `dives_compare` | two runs, and what differs between them |

`sweeps_run` is the one that matters. A single dive is a demonstration. An
agent that designs a pattern, runs it against twelve things nobody can promise,
and comes back with *"it holds until the mooring is ten metres off"* is doing
the work a team was doing.

## Three rules for the server

**Nothing is returned without its provenance.** Including failures: a dive the
platform could not start is not a score of zero.

**Nothing expensive runs without an estimate first.** An agent in a loop can
spend a GPU box in an afternoon. `dives_estimate` exists so the agent can be
told, and quotas exist because it might not listen.

**The agent gets exactly the grants the person does.** Tenancy is already in the
platform. MCP is a door onto it, not a way around it.

## Owed

**`dives_frame` cannot work yet.** No dive in the record has frames, because
every one of them was flown undrawn, and the vehicle packages lost their hulls
in a republish. The image half of the loop — draw a line, fly it, look at what
the camera saw — waits on that being fixed. `layouts_render` does not: a chart
is drawn from data we already hold.

**Transport.** stdio first, because it can be tested today from this session
against the box. HTTP after, because a customer's assistant is not on this
machine.

## And then the vertical

Coral City is a reef platform because a reef was the first thing we built. The
machinery underneath — a place, a vehicle, a mission, a set of doubts, and a
deliverable that says what was measured — has nothing to do with coral.

Inspection is the same shape with different things standing on the ground: a
pipeline, a jacket leg, a quay wall, a hull. The one real change is generalising
*what stands on the seabed* from colonies to features, after which a new case is
a data file rather than a feature.

Not yet, and not in this plan. MCP first, because it is the thing that makes
every later case cheap to demonstrate: a new vertical that an agent can drive
needs no interface written for it at all.
