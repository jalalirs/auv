The gap between "mostly done" and done is one thing in three disguises: **no
real scientific data has been ingested.** The spine that would hold it is built
and proven; what it holds is a text file the end-to-end check uploads. Closing
R1 means ingesting real global bathymetry and a real forecast, tiling them, and
pointing the first city at a real survey.

Experiments and spikes may happen inside a release but never satisfy its gate.

## The three loops

The platform is defined by three loops running at different speeds.

1. **The daily loop** — automated. Global and city observations and forecasts
   land as new canonical layer versions on a schedule. Nobody triggers it. This
   is what makes the platform live rather than an archive.
2. **The evidence loop** — a survey or mission returns, reconstruction runs, a
   new city version is proposed, reviewed, and promoted. Slow, human-gated.
3. **The experiment loop** — an organisation pins a scenario, runs its own
   autonomy stack in our simulator, gets objective scores, iterates.

R1 establishes loop 1 and the governance and provenance that loops 2 and 3
depend on.

## First city

The first city is a site from the NOAA National Coral Reef Monitoring Program
Structure-from-Motion archive. It is chosen on evidence quality, not on
geography — the platform is not specific to any sea.

It is the only surveyed candidate found that carries everything the platform's
discipline requires:

- roughly 1,500 raw JPEG frames per site along 3×20 m transects at 60–80 %
  overlap, which is the input a reconstruction pipeline consumes;
- real georeferencing (GPS latitude and longitude) and real scale (coded
  markers of 0.25–0.50 m plus depth markers with recorded depths), so
  coordinate reference, scale, and a vertical reference are all measured rather
  than assumed;
- a published processing standard operating procedure;
- separately archived derived products — digital elevation models and
  orthomosaics — which give **ground truth to validate our own reconstruction
  against** in R2;
- no access constraints, subject to citing NOAA Fisheries.

One site is a few gigabytes. The full archive is not ingested.

Rejected candidates and why, so the reasoning is not lost: video-only datasets
reconstructed by monocular SLAM carry no coordinates and no scale, and using
one would mean inventing a coordinate reference and a scale factor, which this
platform forbids. Orthomosaic-only datasets are georeferenced but include no
source imagery and no elevation model, so nothing can be reconstructed or
validated from them.

**Open:** a direct retrieval path for the digital elevation models and
orthomosaics of the *same* sites is not yet confirmed. R2's validation gate
depends on it and it must be resolved before R2 is scoped.

## Checkpoints

Each checkpoint is independently reviewable, mergeable, and deployable.

### R1.1 — Platform core: identity, organisations, governance, audit

PostgreSQL with PostGIS in the local and GPU deployments. Migration tooling.
Organisations, people, service principals, scoped role bindings, sessions. The
single access-decision point, built once and called by every route. Grants. The
three discoverability states. Audit on every mutation.

The service `services/control-plane` earns its name here. Today it is a
411-line health service and the name overstates it by an order of magnitude. If
this checkpoint is not approved, the directory must instead be renamed to
`services/platform-api`.

**Gate.** Policy is enforced uniformly, proven by an exhaustive route-table
test rather than by inspection. An unlisted object returns 404; a locked one
returns 403 with a request affordance. Every mutation writes exactly one audit
row with actor, subject, request identifier, and outcome. Every denial writes a
record.

### R1.2 — The world: object storage, layers, versions, provenance

Object storage on a dedicated, size-capped volume. The platform-scoped layer
model with the full provenance metadata set, all fields required. Presigned
upload grants with server-side checksum verification. Immutability: corrections
create versions carrying `supersedes`; no route can mutate or delete a
published layer. Real global bathymetry ingested as the first canonical layer.
Tiling for globe display.

**Gate.** A real global bathymetry layer is versioned, immutable, checksummed,
and renders on a globe. A tampered checksum is rejected and creates no row.
Re-ingesting corrected data creates version 2 while version 1 remains
byte-identical to its original digest. A layer cannot be created without a
coordinate reference, vertical datum, time basis, truth class, and an
uncertainty descriptor.

### R1.3 — Execution and the daily loop

The `exec` schema. `services/worker`. The `local-docker` execution target. The
broker with quota, admissions, and refusals. A durable event stream delivered
to the browser. A **scheduled ingestion job** that pulls a real global ocean or
weather forecast and publishes a new canonical platform layer version every
day, unattended.

This makes the execution spine real using real external data, with no
reconstruction and no GPU.

**Gate.** The platform updates itself daily with real data and nobody touches
it. Killing the worker mid-attempt expires the lease, marks attempt 1 evicted,
and attempt 2 completes — with output recorded exactly once. Exceeding quota
produces a refusal row and a 429 carrying its reason, not a hang. Cancellation
reaches a terminal state within 30 seconds and stops the container.

### R1.4 — The first city and navigation

The city object with extent, coordinate reference, vertical datum, stewards,
and policy. Grants to organisations. City-scoped layers. Contribution, review,
and promotion. The web application: a globe carrying real bathymetry and
today's ocean state, a catalogue, continuous navigation into a city, a
navigable interior at real scale with scale bar and north arrow, a layer stack
panel, and a persistent provenance rail. A generated TypeScript client, with no
hand-written request code.

**Gate.** A visitor signs in, browses the catalogue, enters the city, explores
it in three dimensions at real scale, and reads correct provenance on every
layer — in a browser, on the GPU deployment, with no terminal. A principal
without a grant receives 404 on an unlisted city and a request affordance on a
locked one. A promoted layer becomes visible to all grantees with attribution
and lineage intact, and its object key is unchanged before and after promotion.

## Acceptance tests

Automated unless marked otherwise.

**Governance**

1. Every mutating route requires an authenticated principal and passes through
   the decision point. Failure is a build failure, not a review note.
2. Unlisted city returns 404 without a grant; locked returns 403 with an
   affordance; open returns 200.
3. A viewer binding is refused every mutation; a contributor may upload but not
   promote; only a steward may promote or retract.
4. Revoking an organisation's grant immediately removes catalogue visibility.
5. The API refuses to create a public layer inside a restricted city.
6. Every denial produces a record with principal, object, and reason.

**World, layers, immutability**

7. A correct-digest upload succeeds; a wrong-digest upload is rejected and
   creates no row.
8. No route can mutate or delete a published layer version.
9. A correction creates version 2 with `supersedes`; version 1 remains
   retrievable and byte-identical.
10. Required metadata is enforced at the schema level. An `unknown` uncertainty
    is legal; an absent one is not.
11. Retraction hides a version from default listings and preserves it and its
    lineage.
12. Promotion changes policy only: same object key, same digest, same version,
    plus a review record.

**Execution and the daily loop**

13. Scheduled ingestion runs unattended and publishes a new canonical layer
    version with correct provenance and truth class.
14. Two ingestions of identical upstream data do not create a duplicate version.
15. Worker termination leads to lease expiry, a second attempt, and
    exactly-once output.
16. Output exceeding its declared size cap fails as `output_limit_exceeded` and
    writes no partial layer.
17. Exceeding quota produces a refusal row and a 429 carrying its reason.

**Provenance**

18. A derived layer's lineage resolves to exact input digests, the recipe
    identifier, and the container image digest.
19. A layer derived from a `scenario` input cannot be created with a
    non-`scenario` truth class.

**End to end** (`tools/e2e`, GPU deployment)

20. Fresh deployment, migrate, create organisation, sign in, globe renders real
    bathymetry, enter city, explore in three dimensions at real scale,
    contribute a layer, steward promotes it, it is visible with lineage.
21. Stopping and restarting the deployment preserves all state. Nothing lives
    only in memory.

**Manual, once per checkpoint**

22. Someone who has never seen the repository completes the sign-in, catalogue,
    city, and contribution journey using only `docs/` and the interface.

## Deliberately not included in R1

Stated so it can never be mistakenly claimed.

- **No reconstruction.** Meshes are uploaded artifacts produced elsewhere. R2.
- **No environmental modelling.** Global fields are ingested, not solved. No
  SWAN, WAVEWATCH III, OpenDrift, HYSPLIT, SCHISM, MITgcm, ADCIRC, WRF,
  Delft3D, or FABM/ERSEM/GOTM. R3.
- **No simulator.** No Isaac Sim, no ROS 2, no vessels, no stacks, no
  experiments. **R1 uses no GPU at all.** R4.
- **No missions, telemetry, or field edge.** R5.
- **No Kubernetes, Slurm, or HPC adapter.** One `local-docker` target. The
  interface exists; the adapters do not.
- **No workflow DAG engine.** Single jobs only.
- **No institutional single sign-on.** A local provider behind an adapter
  boundary.
- **No time slider or version comparison.** Requires two real city versions. R2.
- **No high availability, backup automation, or disaster recovery.** R6.
- **No anonymous read**, per ADR-0006.
- **No Electron. No Tauri** until native field-device access is required.

## Operational constraint

The GPU host is a shared workstation, not a cluster: two RTX 5880 Ada cards at
48 GB, 48 cores, 125 GB of memory, and a 1.9 TB root disk that is 82 % full,
already running roughly 30 containers for unrelated projects.

Before storage lands there: a dedicated, size-capped volume; CPU and memory
limits on every Coral City container so that a job cannot take the machine
down; a declared GPU allocation policy; and removal of the stale
`auv-isaac-sim` container left by the discarded legacy tree.

R1 uses no GPU, so only the storage and resource-limit items block it.
